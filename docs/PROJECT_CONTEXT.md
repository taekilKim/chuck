# Chuck — Project Context

> 원본: Google Drive `척척박사 - 콘텐츠 압축 이해 서비스 기획서`
>
> 현재 브랜드 결정: **Chuck**. 아래 문서에서 `척척박사`라는 표현은 아이디어가 발전하던 당시의 과거 가제를 뜻한다.

## 인수인계 목적

이 문서는 이전 ChatGPT 세션에서 발전시킨 서비스 아이디어와 의사결정, 반론, 프로토타입 사례를 보존한다. 새로운 ChatGPT/Codex 작업 세션에서는 이 문서를 먼저 프로젝트 컨텍스트로 읽고 기존 논의를 처음부터 반복하지 않고 이어서 발전시킨다.

아이디어를 모두 확정된 사실처럼 수용하지 않는다. **확정된 제품 원칙 / 현재 가장 유력한 가설 / 장기 아이디어**를 구분한다. 특히 범용 GPT 대비 차별성, 저작권, 희귀 작품 공급 비용, 결과 정확도, 반복 사용 동기는 계속 비판적으로 검토한다.

---

## 프로젝트 정체성

책·영화·드라마 등 문화 콘텐츠를 직접 끝까지 소비하지 않더라도 전체 줄거리, 인물 관계, 복선, 반전, 서술·연출 장치, 결말과 해석, 문화적 대화 포인트까지 빠르게 이해하게 하는 **문화 콘텐츠 압축 이해 서비스**다.

핵심 문장:

> **보고 싶은 콘텐츠와 알고 싶은 콘텐츠는 다르다.**

단순 요약 사이트나 스포일러 사이트보다 **작품 DB가 아니라 작품을 이해시키는 인터페이스**를 지향한다.

서비스는 `Experience the story`와 `Know the story`를 분리한다. 어떤 작품은 직접 경험하고 싶고, 어떤 작품은 경험하지 않아도 충분히 알고 싶다. `알고 싶다`는 욕구 자체를 하나의 완결된 콘텐츠 소비로 인정한다.

## 핵심 사용자 문제와 실제 사례

### Catch Up — 그냥 다 알고 싶다

예: `스카이캐슬`

주제가 취향이 아니고 원작을 볼 의향도 없지만 전체 스토리, 관계도, 복선, 유명 장면, 문화적 맥락은 충분히 알고 싶다. 목적은 시청 전환이 아니라 **이해 자체**다. 화제의 작품을 모르면 주변 대화나 밈을 이해하기 어려운 문화적 FOMO도 이 욕구를 강화한다.

### Decide — 다 알고 나서 볼지 정한다

예: `인디아나 존스 5: 운명의 다이얼`

시간을 쓰기 전에 전체 스토리와 재미 요소를 먼저 확인한다. 스포일러를 모두 본 뒤에도 흥미가 남으면 스트리밍에서 원작을 본다. 요약은 예고편이 아니라 **시간 투자 판단을 위한 전체 정보**다.

### Rediscover — 다시 알고, 다시 빠져든다

예: `Supping with Panthers / Slave of My Thirst`

오래전에 읽었던 작품의 전체 줄거리와 복선을 다시 압축해서 확인하면서 과거의 감상 기억이 재활성화되고 오히려 원작 전체를 다시 읽고 싶은 욕구가 생겼다. 요약은 원작을 대체할 수도 있지만 **원작 재소비를 촉발할 수도 있다.**

## 사용자의 진짜 동기

`아는 척`이나 지적 허영은 하나의 동기지만 전부는 아니다. 더 큰 범주는 다음과 같다.

- 문화적 문해력
- 서사적 호기심
- 시간·체력 절약
- 취향 탐색
- 기억 복원
- 사회적 대화 참여

혼자 있을 때도 스토리를 알고 싶다면 단순한 과시가 아니라 `이야기를 알고 싶은 욕구`다.

## 핵심 가치 제안

- 보지 않아도 알 수 있고, 알고 나서 볼 수도 있다.
- 모든 콘텐츠를 소비하고 싶은 건 아니지만, 알고 싶은 콘텐츠는 많다.
- 보기 전에 알고, 본 뒤에는 더 깊이 안다.

## 범용 GPT와의 관계

범용 GPT가 작품 정보를 답할 수 있다는 사실 자체는 서비스를 무효화하지 않는다. 하지만 `제목 입력 → GPT API → 긴 답변` 수준이라면 차별화가 매우 약하다.

제품 가치는 사용자가 무엇을 질문해야 할지 몰라도 전체 이해에 필요한 질문 구조를 미리 설계하고, 중요한 정보를 선별·편집하고, 결과를 일관된 형식으로 만들며, 다시 찾고 비교하고 공유할 수 있는 안정된 작품 객체로 만드는 데 있다.

중요한 질문은 다음이다.

> **GPT가 답할 수 있나?** 보다 **같은 최종 결과를 얻기 위해 사용자가 해야 할 일을 얼마나 제거하는가?**

단, `프롬프트 노동을 줄여준다`만으로는 방어력이 약하다. 범용 AI가 더 좋아질수록 한 문장으로도 좋은 답을 만들 수 있기 때문이다. 전용 서비스는 구조화, 편집 우선순위, 신뢰 표시, 안정된 페이지, 상태 축적 등 GPT 채팅창에 없는 제품 행동을 만들어야 한다.

사주·궁합 AI 서비스 사례에서 얻은 인사이트는 좋은 Vertical AI가 단순 AI 답변이 아니라 링크 공유, 동일 기준 비교, 시각화, 경쟁, 저장, 네트워크 효과처럼 범용 채팅에 없는 행동을 만들 때 강해진다는 것이다. 다만 콘텐츠 이해는 본질적으로 개인 소비이므로 소셜 기능을 억지로 이식하지 않는다.

## 결과 페이지 방향

긴 AI 답변 한 편이 아니라 **탐색 가능한 작품 지식 지도**를 지향한다.

기본 정보 문법 후보:

1. 1분 핵심 이해
2. 스포일러 포함 전체 줄거리
3. 등장인물 관계
4. 핵심 사건
5. 복선·반전·떡밥
6. 장르·서술·연출 장치
7. 결말과 해석
8. 유명 장면·문화적 대화 포인트
9. 직접 볼 만한지
10. 후속 질문

핵심 요약 뒤에는 사용자가 흥미를 느낀 가지로 바로 이동할 수 있어야 한다. `저수지의 개들`을 이 구조의 유명작 프로토타입으로 검토했다.

## MVP 제1가설

> 사람들은 작품의 전체 내용을 알고 싶을 때 범용 GPT에 직접 질문하거나 검색·위키·블로그·유튜브를 돌아다니는 것보다, 전체 줄거리·인물 관계·복선·반전·장치·결말·대화 포인트가 이미 편집된 **완성된 작품 이해 페이지**를 더 편리하고 가치 있게 느끼며, 한 작품을 본 뒤 다른 작품도 같은 방식으로 연속해서 탐색할 것이다.

MVP는 AI가 줄거리를 생성할 수 있는지 검증하는 프로젝트가 아니다. **Chuck에서 작품을 알아보는 행동 자체가 반복 소비 습관이 되는지** 검증한다.

### 핵심 행동 지표

가장 중요한 초기 행동 지표는:

> **한 작품을 이해한 사용자가 같은 세션 또는 재방문에서 두 번째 작품을 다시 검색하는 비율**

보조 지표 후보:

- 전체 줄거리 도달률
- 복선/반전 섹션 열람률
- 후속 질문률
- 재방문률
- 사용자당 탐색 작품 수
- `GPT나 나무위키보다 편했는가?`
- `다음 작품도 여기서 찾고 싶은가?`

## MVP에서 반드시 필요한 것

- 검색창 하나로 작품을 찾는 진입 경험
- 정확한 작품 식별과 동명이작 처리
- 충분히 상세한 스포일러 포함 전체 줄거리
- 등장인물 관계를 빠르게 이해할 수 있는 표현
- 복선·반전·장치 등 2차 가공 정보
- 결말 및 주요 해석
- 일관된 페이지 템플릿과 읽기 깊이 조절
- 작품별 후속 질문
- 다른 작품으로 자연스럽게 이어지는 검색/탐색
- 자료 충분성 표시
- 기본 행동 로그: 검색, 페이지 진입, 섹션 열람, 체류, 후속 질문, 두 번째 작품 검색 여부

## MVP에서 우선 제외할 것

- 친구 초대와 문화 궁합
- 프로필 간 작품 지식 비교
- 문화력 점수와 랭킹
- 대규모 소셜 피드
- 복잡한 취향 추천 모델
- 세상의 모든 콘텐츠를 사전 구축하는 자체 Full Content DB

이 기능들은 장기적으로 강한 제품 가치를 만들 수 있지만 제1가설을 검증하기 전에는 범위를 넓히는 요소다.

## 데이터 / AI 전략

처음부터 세상 모든 콘텐츠의 Full Content DB를 구축하지 않는다.

초기 기본 구조:

`작품 식별용 얇은 메타데이터 + 외부 자료 검색 + AI 분석/생성 + 생성 결과 캐시`

사용이 쌓이면서 검증된 작품 페이지, 수정 이력, 자료 충분성, 요청 데이터가 자체 Knowledge Cache로 축적된다.

즉 `DB가 필요 없다`가 아니라:

> **처음부터 모든 DB를 만들 필요는 없고, 수요가 생긴 지식부터 자산화한다.**

### 세 계층

**Popular** — 웹 자료가 풍부한 작품. 사전 생성 및 검수.

**Long tail** — 일부 자료가 있는 작품. 최초 요청 시 생성하고 캐시.

**Dark Catalog** — 절판·오래된 책·마이너 영화처럼 공개 정보가 거의 없는 작품. 확인 가능한 정보까지만 제공하고 요청을 축적한다.

희귀 작품은 사용자 1인당 가치가 높을 수 있지만 총수요가 낮을 수 있으므로 모든 작품을 미리 구축하지 않는다.

## 최상위 신뢰 규칙

> **근거가 없으면 생성하지 않는다.**

공개 자료에서 확인되지 않는 사건, 인물, 결말, 복선 등을 AI가 그럴듯하게 채우지 않는다.

- 사실
- 강한 추론
- 해석
- 확인 불가

를 구분한다.

자료가 부족하면 불완전한 결과를 정상 상태로 인정하고 `Coverage Level` 또는 자료 충분성을 표시한다.

### Dark Catalog 검색 UX 사례

`황금말을 찾아서` 검색 사례에서는 작품 식별과 일부 설정은 확인됐지만 전체 줄거리와 결말은 신뢰성 있게 확보되지 않았다. 이런 경우 확인된 정보와 확인되지 않은 정보를 분리하고 `이 작품 전체 내용 요청하기`를 제공한다.

Dark Catalog의 실제 조사·구축 운영 시스템은 MVP 제1가설 검증 이후의 2단계 후보다.

## 저작권 및 콘텐츠 원칙

- 소설 원문을 그대로 재현하거나 장문 인용하지 않는다.
- 영화·드라마 원본 영상, 캡처 화면, 장면 이미지를 결과물에 사용하는 것을 기본적으로 피한다.
- 사실의 재구성, 인물 관계 설명, 복선·반전 분석, 서술·연출 장치 해설, 결말 해석 등 독자적 편집·분석이 개입된 결과를 지향한다.
- `해석을 거쳤다`, `2차 창작이다`라는 이유만으로 법적 리스크가 자동 제거된다고 보지 않는다.
- 제품 정책은 **표현 복제 최소화 + 독자적 분석·비평 중심 + 필요한 범위만 사용 + 원작 시장 대체 위험 관리**다.
- 상용화 시 별도 법률 검토가 필요하다.

## 제품 원칙

- 스포일러 포함을 기본값으로 하되 사용자가 명확히 인지하도록 한다.
- 사실관계와 해석을 구분한다.
- 불확실한 내용은 불확실하다고 표시한다.
- 원문·영상 장면을 대량 복제하지 않고 요약·설명·분석 중심으로 구성한다.
- 원작을 보지 않는 선택도 존중한다.
- 요약 이후 원작을 보고 싶어진 사용자에게는 자연스럽게 다음 행동을 연결한다.

## 장기 확장 가설 — 아직 MVP 범위 아님

- 이해한 작품을 개인 문화 라이브러리에 축적
- 직접 본 작품 / 내용만 아는 작품 / 다시 볼 작품 구분
- 장르·서사 취향과 문화 지식 프로필
- 작품 취향 지도
- 친구와 겹치는 작품 / 서로 모르는 작품 비교
- 공유 가능한 `5분만 읽고 와` 링크

이들은 확정 기능이 아니라 제1가설 검증 이후의 가설이다.

## 현재 권장 작업 순서

1. MVP 실제 화면 / 정보구조 개선
2. Popular / Long tail / Dark Catalog 각각의 검색 결과 상태 정의
3. 제1가설 검증 실험과 성공/실패 기준 구체화
4. 데이터 수집·검색·캐시·검수 기술 아키텍처
5. 초기 100~300개 작품 선정 및 품질 기준
6. GPT/나무위키 대신 반복 사용하게 만드는 추가 차별화 검증

현재 대화에서 웹 MVP를 먼저 만들기로 결정했으므로 구현 작업이 우선될 수 있다.

## 현재 구현 방향

- 앱이 아니라 웹 MVP
- Next.js App Router
- Vercel 배포
- Supabase는 검색 로그, 요청 데이터, 향후 콘텐츠 저장을 위해 연동 예정
- 처음부터 모든 작품을 지원하지 않아도 됨. 초기에는 제한된 작품으로 결과 페이지 경험과 반복 탐색 가설을 검증할 수 있음.

## AI에게

사용자가 가설을 확인하는 질문을 하더라도 무조건 동의하지 않는다. 맞는 부분과 틀릴 수 있는 부분, 반론과 대안을 함께 제시한다.

새 기능이나 기술을 제안하기 전에 반드시 다음을 확인한다.

1. 이 기능이 MVP 제1가설을 검증하는 데 필요한가?

이 서비스 아이디어는 `Supping with Panthers / Slave of My Thirst`라는 오래된 작품을 희미한 기억만으로 찾은 뒤, 전체 스토리 → 결말 → 복선까지 연속해서 파고드는 실제 대화 경험에서 출발했다. 이후 `스카이캐슬`의 Catch Up, `인디아나 존스 5`의 Decide 사례를 더하면서 세 핵심 사용 맥락이 정리됐다.
